## 一、30 秒电梯陈述（评委刚走近时）

"上游 PilotDeck 压缩上下文时，把历史一刀切成一段摘要——精确数字、文件路径、检查点全部有损。我们给 CompactionEngine 加了一层**评分式选择性保留**：把将被摘要的消息按 `0.85×语义相关性 + 0.15×艾宾浩斯时近度` 打分（第三项实体图核心度保留在代码里、默认权重 0），高价值消息**逐字**保留。效果：压缩后 token 约 1.11–1.20 倍，长对话精确事实恢复从 **0/20 提到 17.9/20**（英文 N=160，**10 个从未参与调参的 seed 上 10 胜 0 平 0 负，符号检验 p=0.002**）；消融、留出集、话题切换、真 LLM 闭环各自有独立账本。"

## 二、2 分钟展位讲解流程

1. **痛点演示（30 秒）**：跑 `pnpm benchmark:demo`——一条 80 轮生信对话，20 条精确事实被上游全部压进摘要；问"TP53 的突变频率是多少"，摘要答不出。
2. **机制（30 秒）**：白板/海报上画公式 `S(m) = 0.85·sim + 0.15·time + 0.00·IDF-PageRank`，三句话讲三个分量：语义对准用户当前请求；时近度用艾宾浩斯衰减；实体图找"被反复讨论的核心实体"（第三项默认权重 0，原因见 Q1，别被问住）。强调中文处理：**免分词 bigram + 高频功能词剪枝 + IDF 校正**。
3. **证据（40 秒）**：海报数字区——留出集主表 + 消融表 + 真 LLM 问答准确率。每指一个数说一句"怎么来的、怎么复现"。（话题切换表**不上海报**：旧话题那一列经诊断是 harness 句式共享造成的假象，见卡 3。）
4. **工程素养收尾（20 秒）**："所有改动有 no-regression 守护：不启用 scorePolicy 时与上游基线**逐字节一致**；全仓 517 项测试、515 通过 / 0 失败 / 0 cancelled / 2 skipped；打分开销毫秒级、相比一次 LLM 摘要调用占比 5–15%。"

## 三、三大证据卡（对应评分维度）

### 卡 1 · 技术深度
- 评分式保留公式三项可插拔（`scorePolicy` 注入，不破坏上游字节级兼容）
- **双语实体抽取**：ASCII 大写驼峰 + 中文滑动 bigram（免分词），文档频率剪枝功能词
- **消融驱动的三轮修复**（有完整过程可讲）：
  1. 消融发现原始 PageRank 单独使用 0 分 → 机制分析：共现枢纽是重复噪音 → **IDF 校正** `log(1+M/df)` → 中文 rank 项 0 → 3.5
  2. 消融发现旧权重让 time/rank 稀释主力 sim 项 → 18 配置网格搜索重锚（argmax 72/120）→ 新默认在消融表 6 个格子里全第一
  3. 留出集复核发现**代码默认值写偏了**（写的是 0.7/0.15/0.15，而网格 argmax 是 0.85/0.15/0.00）→ 对齐常量，并给 `holdout.ts` 加了防漂移（直接读常量而非抄字面量）
- 消融表（调参协议中位数，facts/20）：

| 变体 | EN N=160 | ZH N=160 |
| --- | ---: | ---: |
| sim only | 16 | 8 |
| time only | 2 | 2 |
| rank only（原始） | 0 | 0 |
| rank only（+IDF） | 0 | 1.5 |
| full 旧默认 0.4/0.35/0.25 | 10.5 | 6 |
| **full 当前默认 0.85/0.15/0.00** | **18** | **10** |

### 卡 2 · 效率
- 压缩后 token：Hippo ≈ 上游的 **1.11–1.20×**（换回逐字事实）——这是**多付**的代价，要主动说，别写成像省了 token
- 打分延迟（本地计算，无网络）：EN 13–50ms，ZH 135–369ms（消融 JSON 的 `wallMsMedian` 极值，N=40→160）；对比真 LLM 摘要调用秒级，占比 ≈5–15%，且压缩是低频事件
- 真 LLM 账本（`benchmark:real-llm`）：摘要调用 token、评审 token、墙钟时间全部落 JSON——"我们不只说省 token，我们把每次压缩的 token 去哪了记了账"
- 记忆卡未来可跨轮复用（读取侧索引在路线图），一次压缩的成本摊薄到多轮

### 卡 3 · Agent 更聪明
- 主基准（fake summarizer，结构对比）：精确事实恢复 **0/20 → 8、9、18**（N=40/80/160，调参协议中位数；留出集口径见下方数字区）
- **话题切换**（回答"中途换话题，旧上下文还在不在"）：两套 harness、两个结论，**都要主动说，别等评委问**。
  - **stub 摘要器口径**（`benchmark:topic-switch`，快、可现场跑）：当前话题的精确事实逐字保留 **6/10 → 10/10**，两种措辞下都成立（README §4.6）。但这个 6/10 里有 stub 摘要器的成分，**所以这条只是结构对比，不要讲成"用户能多答对多少"**。
  - **真摘要器口径**（`benchmark:real-llm-topic-switch`，README §4.7）：这条优势**是有条件的**，两轮都讲。①**摘要预算宽裕**（8000 tok）时测不出差异——真摘要器自己就把检查点抄进摘要，上游当前话题也 16/16 全对，旧话题上游同样 16/16（靠摘要、不靠保留块）；而且同配置两次重复的摆动就有 3–4 题，摆动大于臂差，**这一轮我们只报机制、不报方向**。②**摘要预算吃紧**（1500 tok）时给出全仓最干净的一条正向结论：**当前话题 10/16 → 16/16，两种措辞同向，Hippo 四次重复零摆动**（上游自己重复间摆动 2 题），臂差约为摆动的 3 倍。③机制上最诚实的一句：**两臂的摘要触顶次数几乎一样多**（3 vs 4 / 共 4 例），所以"上游被截断、Hippo 没被截断"不是解释；解释是保留块逐字带着当前话题的检查点（8/10 vs 上游 6/10），摘要写没写完都不影响它。**一句话：保留的价值在摘要器扛不住预算时显现。**
  - **旧话题 A 列不要对外讲**：`benchmark:topic-diagnosis` 查实最原始的 2/5.9 是假象——`time only`/`rank only` 都是 0/10，`sim only` 单独就复现 5.0/10，A 段事实对 B 请求的 BM25 是 0.820 vs 填充 0.240，改写成不含共享标签的散文后掉到 0.370，即 (0.820−0.370)/(0.820−0.240) ≈ **78% 的相似度落差来自 A/B 事实共用同一句式模板**；换成 `decorrelated` 措辞后 A 列归零。真摘要器路径上这个假象同样重现（`shared` 保留区 6/10 → `decorrelated` 归 0，上游两种措辞都是 0），两套 harness 互相印证。
  - 结论一句话：**Hippo 的收益是"对当前任务保真 + 保留是确定性的"，不是"记住旧话题"**。被追问时照实说，现场可跑诊断脚本与真 LLM 脚本自证。
- 真 LLM 闭环（DeepSeek-V4-Flash 真摘要 + 同模型评审，压缩后只能靠上下文答题）。**同一天跑了两个条件，必须两轮一起讲**——只讲 A 轮会被现场问倒：

| 轮次（摘要预算） | 场景 | 上游 | Hippo |
| --- | --- | ---: | ---: |
| A 官方 API（摘要短：1,200 tok/次） | EN N=160 | 12.5% | **87.5%** |
| A 官方 API | ZH N=160 | 0% | **81.3%** |
| A 官方 API | EN N=80 | 68.8% | 68.8%（打平） |
| B 比赛网关（摘要上限 4,000 tok/次，≥8/16 次触顶） | EN N=160 | 100% | 100%（打平） |
| B 比赛网关 | ZH N=160 | 31.3% | **56.3%** |
| B 比赛网关 | ZH N=80 | 0% | **62.5%** |

  一句话：**中文任务两轮 4/4 格 Hippo 占优；英文任务的结果随摘要长度变化**——摘要一长（A 轮 1,200 tok/次 → B 轮 ≥2,633 tok/次），上游靠把检查点逐条抄进摘要也能回到 100%（代价是摘要 token 上浮）。**长度和得分同向是实测的；"A 轮被截断"是推断**——A 轮实际生效的上限值没落库，现场被追问就照实说这一句。所以我们的口径是"方向性结论"，**不宣称单一提升点数**，被追问 A 轮的 12.5%→87.5% 时主动把 B 轮端上去。
- 中文同等有效：`generateZhTranscript` 中文对话上 Hippo > 上游（有专项测试）
- **提取精度（回答评委"你怎么保证提取得准？有没有打分？"）**：`retention.retainedMessageTexts`（评分选中并真正进入压缩后上下文的**逐字消息**，不用指纹反推、无重建伪影）做逐消息精/召回，留出集 seed 上 `pnpm benchmark:extraction`：**精度 89–100%（多为 100%，2.7–11× 高于随机基线）**——保留块几乎全是需要的当前话题，不是把整段历史一股脑塞回；召回受 ≤256 tok 预算限制只带 4–16 条，代价明写在表里（用掉 88–99%）。照实讲一句：**这不保证任意真实任务选得对，打分仍是无监督启发式；它保证一旦选中几乎必然相关且逐字无损**。

## 五、预答辩 Q&A（评委可能怎么问）

**Q1：公式第三项权重为什么是 0？那不就是把组件删了吗？**
> 没删，代码、实体图、`wRank` 配置项都在，一行配置就能启用。留出集配对检验里它 **7 胜 33 平 0 负、四个格子无一显著**（p=1/0.5/1/0.125）——去重它不吃亏，但也没带来可测量的收益，所以按"少一项"取了 0。它真正有信号的位置是**无 query 场景**（中文 no-query 探针 rank+IDF 2.8/20 vs 纯 sim 1.0/20），而那个场景我们后来从成因上修掉了（见 Q1b），所以不必靠加权重去兜。
> 注意口径：我们**不**说"权重优化带来了提升"。改默认值的理由是"对齐调参 argmax + 更简单"，不是涨分。

**Q1b：无 query 场景是什么？你们怎么修的？**
> 压缩不一定由新用户请求触发——一条超长工具输出撑爆预算同样触发。那时 tail 里没有用户消息，`queryHint` 会退化成空串，语义项直接归零，留出集探针实测只保留 0.00–0.20/20 条事实。我们修的是**成因**不是权重：现在找不到就回退到"全对话中最近的一条真实用户请求"。回归测试在撤销修复后确定性失败（策略收到空串），修复后通过。

**Q2：消融显示 time 单独很弱，为什么还留着？**
> 消融的口径是"单独使用"。合成分布事实偏前、query 在尾，time 天然反相关——这是分布特性不是组件缺陷。组合上当前默认在消融表 6 个格子全第一，网格 argmax 72/120 也含它。权重是网格搜索出来的，不是拍脑袋。

**Q3：中文为什么不用分词器？**
> 分词器是重依赖且领域词表要维护。滑动 bigram 免分词、零依赖、确定性，配合文档频率剪枝去功能词、IDF 校正去枢纽效应，在基准上已过专项测试。代价是实体数膨胀（延迟 135–369ms），仍远低于一次 LLM 调用，且有截断参数可调。

**Q4：合成基准会不会过拟合？**
> 我们把"选参数"和"报成绩"分开了：权重只在 ≤20260920 的种子上选，对外成绩一律用 20260921–20260930 这 10 个**从未参与选择**的种子，配对符号检验（`benchmark:holdout`），JSON 随仓库提交。主效应对上游四格全 10 胜 0 平 0 负；而"当前默认 vs 上一版默认"这一对比留出集上并不显著（7 胜 33 平 0 负），我们照实写进 README，也不拿它当成绩。另有两轮机制修复（IDF 校正、剪枝）是分布无关的原理性修正。

**Q5：真 LLM 摘要也很强，上游还会是 0 分吗？**
> 真 LLM 闭环里上游确实不是 0 分：短对话强摘要模型能兜住（EN N=80 打平 68.8%），它甚至会自发把检查点抄进摘要。但压力一大（N=160）就崩——A 轮 EN 12.5%、ZH 0%，Hippo 同场景 87.5%/81.3%（**如实说**：A 轮摘要只有 1,200 tok/次，这个崩盘里有多少是"有损机制"、多少是"摘要被截断"我们没测到，B 轮摘写长了上游就回到 100%）。真正两轮都站得住的是中文那 4 格，以及"保留块逐字带着检查点、不依赖摘要模型"这一点。

**Q6：为什么不直接换更强的摘要模型？**
> 换模型改变的是"有损压缩的质量上限"，不改变"有损"本身；且更强模型更贵。Hippo 是正交改进：任何摘要模型之上都能叠加，包括端侧小模型（赛事 100 元端侧额度正好够 BGE embedding）。

**Q7：延迟 / 成本？**
> 打分毫秒级本地计算（卡 2 有数）；真 LLM 闭环**两轮合计** 32 次摘要调用 + 256 道问答评审（每轮 16 次 + 128 道），共 **140.8 万 tokens**（A 轮 65.5 万 + B 轮 75.3 万，含 judge 的 prompt），全程走 flash 档——有完整的 token 账本可查（两轮 JSON 随仓库提交，每格都记了 prompt/completion/judge 三笔）。

**Q8：你们说"换话题后旧话题还在"，这个怎么证明不是基准的假象？**
> 我们自己查了，**旧话题那一列确实是假象，而且已经修了**。`benchmark:topic-diagnosis` 把同批转录稿拆成单目标权重跑：`time only` 和 `rank only` 都保留 **0/10**，`sim only` 单独复现 5.0/10；直接量 BM25，A 段事实对 B 请求是 0.820、填充消息只有 0.240——因为两类事实共用同一套字段模板。把事实写成不含共享标签的散文后掉到 0.370——(0.820 − 0.370) / (0.820 − 0.240) ≈ **78% 的相似度落差来自共享句式**（0.240 是 A 段填充消息的基线）。所以我们给 harness 加了 `decorrelated` 措辞（两话题各自用词、请求只用 B 的词）重跑：**旧话题 A 列归零，与上游一致**。
> 更进一步：我们又用真摘要器重做了整个话题切换实验（`benchmark:real-llm-topic-switch`），而且**把预算当成自变量跑了两轮**，两轮都端上来：预算宽裕（8000 tok）时确实测不出差异——真摘要器自己会把检查点抄进摘要，**旧话题答得对不能算在保留块头上**（上游没有保留块，旧话题照样 16/16 全对，它的 A 段事实 8/10 只出现在摘要里），且同配置重复的摆动就有 3–4 题，摆动大于臂差，这一轮我们只报机制。把预算压到吃紧（1500 tok）后，情况反过来：**当前话题 10/16 → 16/16，两种措辞同向、Hippo 四次重复零摆动**，臂差约是上游自身摆动的 3 倍；而两臂的摘要触顶次数几乎一样多（3 vs 4），所以这不是"把上游截断了"——是保留块逐字带着检查点，摘要写没写完都无所谓。
> 我们现在的对外口径是两句：**①当前话题的精确事实：预算吃紧时 10/16 → 16/16（真摘要器）、预算宽裕时无差异，结构对比在 stub 口径下是 6/10 → 10/10；②保留是确定性的——当前话题保留区 8/10 vs 上游 6/10，不依赖摘要模型，重复零摆动**。Hippo 的收益是"对当前任务保真 + 保留确定"，不是"记住旧话题"——这句话我们敢当着评委说，因为它经得起现场跑脚本，包括跑一次把自己的结论证伪的那个脚本。
