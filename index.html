PilotDeck · bug fix · 2026-09-12

Two retention bugs, fixed and shown running

PilotDeck compresses long agent conversations. Its Hippo policy keeps a few messages word-for-word instead of folding everything into a summary. Two defects in the selection and rendering path were fixed today; this page states them and shows the live run that proves both.

1 — The defects

Defect 1: a "kept" message could carry no visible text

An assistant turn can contain only a thinking block. On replay that becomes an empty assistant message (content: ""), with the text riding in reasoning_content, which an OpenAI-compatible endpoint may ignore. The thinking text often sits near the user's question, so such a candidate scored high and was selected: it spent retention budget and was reported as kept while delivering nothing. The fix is in src/context/compaction/retention/EbbinghausPageRankPolicy.ts, inside pickRetained: 

    for (const entry of scored) {
      const tokens = input.estimateTokens([entry.message]);
      if (tokens <= 0) continue;
      // A candidate with no visible text (e.g. an assistant turn that carries
      // only a `thinking` block) would be charged against the retention budget
      // and replayed as an empty message. Keeping it spends budget to deliver
      // nothing, so it must not be retained -- fall through to the next one.
      if (messageVisibleText(entry.message).length === 0) continue;
      if (usedTokens + tokens > input.retentionBudgetTokens) continue;
      retained.push(entry.message);
      usedTokens += tokens;

Paired change in src/context/compaction/retention/MessageText.ts: the thinking case no longer contributes to the "visible text" used for scoring. Scoring and replayability now agree.

Defect 2: the retention summary never reached the screen

The UI has two chat panes. The rendered one is v2. Its grouping code folds the compaction boundary into a synthetic "process" row and drops the boundary itself from detailMessages before rendering, so the boundary's retention summary was lost before any component could draw it. The v1 pane read the boundary directly and drew it fine; v2 never did.

Fix, across three files: ui/src/components/chat-v2/processGrouping.ts copies compactRetention onto the synthetic summary; ui/src/components/chat-v2/ProcessTrace.tsx gained an optional badge slot; ui/src/components/chat-v2/MessageRowV2.tsx renders the pill. The pill renders nothing when the policy kept zero messages, so an upstream engine never claims a badge.

3 — Tests

  • tests/context/hippo-retention.spec.ts (new): messageVisibleText ignores thinking blocks, pickRetained never keeps a candidate with no visible content.
  • ui/src/components/chat-v2/processGrouping.test.ts (new): carries the retention summary off the folded boundary onto the process row, reports no retention summary when the boundary carried none — file total 24 passed.

On the old code the two retention-spec tests fail and the "carries the retention summary" test fails: the retained-set assertions reject the thinking-only turn, and the folded process row has no compactRetention to compare. The fourth test is a no-regression guard — it passes either way.

Suite counts: ui chat-v2 suite 13 files, 114 tests passed. Root repo suite exit code 0 (517 passed, 2 skipped, 0 failed).

npm test                                                        # repo root, exit 0
Context budget. Compaction only fires when the live context crosses the threshold, so a demo needs a small budget. A temporary agent.maxContextTokens was set for this recording (in ~/.pilotdeck/pilotdeck.yaml) and restored afterwards. The demo forces compaction early by lowering the budget; under the normal budget the same path runs, only later. No product code was changed to produce the recording.

5 — What this does not show

  • The recording is a scripted UI session — Playwright typing into the app — not a human. It is the real built UI and a real model, but the input is automated.
  • The retention policy itself is the project's existing ebbinghaus-pagerank policy, unchanged by this work. These fixes change which messages are eligible and whether the summary renders, not how messages are scored or ranked.
